# WheelPlay CarLink 插件使用指南

CarLink 插件把发送手机的车联界面接入 WheelPlay，再由车机浏览器显示。插件与
WheelPlay 都安装在**接收手机**上；发送手机需要具备兼容的 ICCOA CarLink 车联功能。

Wi-Fi Direct、手动热点、USB，以及 Surface / WebRTC 输出均已通过实机验证。
验证结果适用于已测试的设备，不代表所有手机或车机浏览器都兼容。

## 安装与升级

- 接收手机：Android 9 或更高版本，arm64，4 KB 内存页。当前 SDK 不支持 16 KB 内存页。
- 同时更新 WheelPlay 和 CarLink 插件。插件使用 API v2；WebRTC 需要宿主支持压缩视频扩展 v1。
  不兼容时请更新同一发布批次的宿主，或先使用 Surface 输出。
- GitHub Actions 的 **Android Debug Build** 中，`wheelplay-debug-apk` 是宿主，
  `wheelplay-carlink-debug-apk` 是插件。插件 artifact 同时包含 APK 和 `carlink-build.json`。
  CI Debug 用于测试；正式发布使用 Release 签名产物。
- Debug 插件包名为 `moe.feng.wheelplay.plugin.carlink.debug`；Release 为
  `moe.feng.wheelplay.plugin.carlink`。两者配置独立，建议只启用一个，避免输入源重复。
- 相同包名、相同签名的升级可覆盖安装并保留配置。早期本地 Debug 曾使用 Release 包名，
  如果新 APK 提示签名不一致，先记录设置，再手动卸载旧插件后安装；卸载会清除插件配置。
  不需要为此清除 WheelPlay 数据。CI Debug 在不同构建间可能使用不同调试签名，不能保证覆盖升级。

安装后，在 WheelPlay 的“输入源”中启用 **ICCOA CarLink**，打开插件设置选择连接方式。
打开设置本身不会启动投影；准备好设备后，返回 WheelPlay 点击“连接”。
缺少权限时会自动进入 CarLink 准备页，由插件申请权限；完成后自动返回并继续连接。
拒绝授权后可打开插件应用权限设置，也可取消连接；系统定位或无线开关未开启时，准备页提供相应设置入口。
首次配对的六位码会直接显示在 WheelPlay 首页的连接状态卡中，标注为“CarLink 配对码”，
请按发送手机的车联提示输入；它与浏览器连接 WheelPlay 的配对码不同。连接完成、失败或停止后不再显示。

设置页会显示“等待 USB 授权”“等待手机确认”“等待画面”等连接阶段。手机投影就绪后，
仍需在浏览器启动显示。出错时会保留原因并提供对应的设置或返回重连入口。
已保存的连接方式、视频模式与当前会话分别显示；修改后提示“已保存，下次连接生效”。
热点名称和密码各自显示校验提示，名称同时显示字符数和 UTF-8 字节数。
画质、缩放、DPI 和画面诊断位于默认折叠的“高级设置与诊断”中。

## 选择连接方式

| 连接方式 | 准备步骤 | 车机浏览器如何联网 |
| --- | --- | --- |
| Wi-Fi Direct（默认） | 两部手机开启 Wi-Fi、蓝牙和定位；接收手机授予附近设备与定位权限。在发送手机车联功能中选择接收设备并确认配对。 | 浏览器和接收手机连接同一局域网；手机间 P2P 链路与浏览器链路是两条连接。 |
| 手动热点 | 在接收手机系统设置中开启热点，在插件中填写完全相同的名称和 WPA2 密码；开启蓝牙及所需权限，在发送手机车联功能中选择接收设备。 | 车机浏览器可连接接收手机的热点。 |
| USB | 接收手机支持 USB Host / OTG；用数据线连接发送手机。从 WheelPlay 发起连接，允许 USB 访问及发送手机上的车联确认。切换配件模式时可能需要再次授权。 | USB 连接两部手机；车机浏览器仍需通过 Wi-Fi / 热点访问接收手机。 |

手动热点名称必须为 **9～32 个字符**，且 UTF-8 编码不能超过 32 字节。
密码为 **8～63 位英文、数字或符号**，必须与系统热点一致。插件不会代开、修改或关闭系统热点；
名称和密码只保存在本机插件配置中。

USB 模式只连接一台发送手机，无需为手机间的 USB 传输开启蓝牙或 Wi-Fi。
每次修改连接方式后，请先停止当前投影，再重新连接。

## 打开车机画面

1. 在车机浏览器打开 WheelPlay 显示的局域网地址。
2. 按页面提示完成浏览器配对，再点击“启动显示”。浏览器配对与手机 CarLink 配对互相独立。
3. 等待发送手机连接后，即可显示画面并使用单指触控。只保留一个已连接的浏览器显示页面。

| 输出方式 | 适合的场景 | 设置说明 |
| --- | --- | --- |
| 兼容模式（Surface，默认） | 需要 JPEG / WebP 图片兼容输出的浏览器 | 可调图片格式、质量和发布帧率；这些设置只作用于此模式。 |
| 低延迟视频模式（WebRTC） | 浏览器支持 H.264 / WebRTC，希望减少接收手机解码和图片编码开销 | 浏览器直接解码；新连接可能等待关键帧，不使用图片质量或图片帧率设置。 |

输出方式更改在下次连接生效。浏览器自适应尺寸变化可能触发手机端重新连接；
请根据发送手机提示确认。当前支持单指触控；音频可能由接收手机播放，暂不提供浏览器音频、
浏览器麦克风、语音唤醒或摄像头转发。

## 故障恢复

| 现象 | 操作 |
| --- | --- |
| **USB 错误 10007，或停止后 USB 重连超时** | **断开两部手机之间的 USB 线，再重新插入。** 保持发送手机解锁，在 WheelPlay 重新连接，并允许 USB 访问和手机端车联提示。不要只反复点击连接。 |
| 找不到无线接收设备 / 配对超时 | 检查两部手机的 Wi-Fi、蓝牙、定位和接收手机的附近设备权限；从发送手机的车联功能重新选择设备，再从 WheelPlay 连接。 |
| 热点名称或密码错误 / 热点网络未找到 | 确认接收手机系统热点已开启，插件名称和密码完全一致；名称符合 9～32 字符及 32 字节限制。若有旧 Wi-Fi Direct 连接，先断开它再试。 |
| USB 授权被拒绝 | 断开数据线后重连，从 WheelPlay 发起连接，并在接收手机的系统对话框中允许访问。确认数据线支持数据传输、接收手机支持 OTG。 |
| 浏览器打不开地址 / 断线 | 检查浏览器和接收手机的局域网连接，使用 WheelPlay 当前显示的地址；手机间 USB 或 P2P 连通不代表浏览器链路也连通。 |
| “已有车机连接” | 关闭或断开其他已连接的浏览器显示页面，再启动当前页面。 |
| 持续黑屏或等待关键帧超时 | 停止投影后重新连接；也可在插件中选择 Surface 后重连。USB 重连报 10007 时按第一项拔插数据线。 |
| 插件清理失败、已隔离、残留 P2P 组 | 先断开 USB；无线连接请关闭再开启系统 Wi-Fi，以清除旧连接，再重启 WheelPlay。不要只强行切换输入源。 |
| 提示架构、4 KB 内存页不支持 | 当前 SDK 无法在此接收设备上运行，请换用符合条件的接收手机。改变画面设置不能解决该问题。 |
| 宿主不支持插件 / WebRTC | 同时更新 WheelPlay 与插件；旧宿主可先尝试 Surface。插件未出现时确认已安装在同一 Android 用户空间，并在输入源中刷新、启用。 |

正常退出请使用 WheelPlay 的“停止投影”，等待连接资源释放，再切换输入源或关闭应用。
手动热点不会随停止投影关闭，需要时请在系统设置中自行关闭。

可在“高级设置与诊断 → 复制诊断信息”获取版本、连接和输出方式、画面尺寸、阶段与错误码。
复制内容不含热点名称、密码、配对码、设备标识或原始错误文本。宿主版本需从新版 WheelPlay
的插件设置入口打开才能获取；独立打开时会提示来源缺失。

反馈问题时，请附接收手机和发送手机型号、系统版本、车联客户端版本、宿主与插件版本、
连接方式、输出方式、错误码和复现步骤。截图或日志请去掉热点密码、配对码和设备标识。

开发、签名及产物校验见 [CarLink 构建说明](CARLINK.md)。
