# 浏览器音频与麦克风

在 Android App 的「设置 → 画面与音频」分别打开「转发音频到浏览器」和「使用浏览器麦克风」。两项默认关闭，可单独切换并立即生效；断开时暂时恢复 Android 路由，重新配对后会继续使用已保存的设置。浏览器可能要求点按画面以启动音频播放，网页不提供转发开关。音频播放可在普通局域网 HTTP 页面使用，与现有 JPEG / WebRTC 视频模式独立。

浏览器麦克风需要可信安全上下文。普通局域网 `http://设备地址:8080` 页面不能申请麦克风权限。配置步骤：

1. 在「设置 → Web 监听」打开「启用 HTTPS」。在「设置 → 权限与连接帮助 → 浏览器 HTTPS 证书」查看本设备的 SHA-256 指纹。在车机配对页展开「浏览器麦克风需要 HTTPS」，等待页面显示指纹并逐字核对，然后下载本地证书。
2. 在车机浏览器或系统中按其支持的方式信任此证书。随后打开页面提供的 `https://设备地址:HTTPS端口/` 链接（默认 `8443`），重新配对。
3. 在 App 设置中打开「使用浏览器麦克风」，按浏览器提示授权。仅在 iPhone 发起通话或语音输入并要求麦克风数据时，浏览器采样才会发送到服务端。

证书的私钥只保存在 Android 应用的私有、非备份存储中。默认 HTTPS 证书包含启动时的局域网地址，以及配置的共享 IP/域名。共享 IP/域名修改后自动刷新默认服务器证书；其他局域网地址变化后请重新启动服务。如果车机浏览器不能信任本地证书、禁用了麦克风权限或不支持 AudioWorklet，请使用 Android 麦克风。请勿通过浏览器的证书警告强行继续访问。

## Web 监听与 HTTPS 证书

「设置 → Web 监听」包含 HTTP 端口（默认 `8080`）、Web 域名和 HTTPS 开关，无需 Root。Web 域名同时用于 HTTP 与 HTTPS，DNS 需解析到实际访问 IP，自定义 HTTPS 证书需覆盖该域名。HTTPS 默认开启；关闭后停止 TLS 监听，隐藏 HTTPS 端口和证书设置，保留证书与端口配置，HTTP 和配对状态继续可用。

开启 HTTPS 后可修改「Web HTTPS 端口」（默认 `8443`）。HTTP / HTTPS 实际监听端口范围均为 `1024–65535`，两者不能相同。运行中先绑定新端口；占用或绑定失败会保留原监听器和保存值。成功后浏览器需重新连接，配对令牌和 iPhone 媒体会话保留；网页的「打开 HTTPS 页面」同步使用新端口。设置重启后仍有效。

使用 `80` / `443` 等低位端口时，在「设置 → Tesla 兼容（实验）」第一行请求 Root 权限。授权成功后显示映射端口与访问 IP 设置；开启系统热点及此模式后，通过 Root 将访问 IP 的低位端口转发到 Web 监听高位端口。映射规则与热点路由统一安装和清理，失败不影响普通 Web 服务。普通 App 直接绑定低位端口可能得到 `EACCES`，仅对路由 shell 授权不会改变 App 进程的绑定权限。详见 [Tesla 兼容说明](TESLA_HTTP.md)。

证书类型选择器直接显示在 Web 监听页面上：

- **PEM**：先通过系统文件选择器选证书文件，再选私钥文件。证书链按服务器证书、签发者顺序排列；支持 PKCS#8、RSA、EC PEM 私钥及加密 PEM，未加密时密码留空。传统 EC 私钥可带一个前置 `EC PARAMETERS` 块（命名曲线或显式参数）；仍须仅包含一把私钥，不接受额外尾随对象。
- **PKCS#12**：选择 `.p12` 或 `.pfx`，输入文件密码。若有多个私钥条目，会列出别名供选择；可输入不同的私钥密码，留空表示使用文件密码。空密码容器也可导入。
- **默认本地证书**：选择后撤销自定义身份，重新使用本安装的本地 CA 签发服务器证书。

选择 PEM 或 PKCS#12 后显示对应文件选择按钮，导入成功前继续使用当前证书。每个文件最多 2 MiB。导入会验证有效期、服务器用途、证书链顺序/签名和证书与私钥匹配。无效文件、密码错误或私钥不匹配时保留原证书。有效身份规范化后原子保存到 `noBackupFilesDir`；不持久保存导入密码，也不向网页暴露私钥。文件选择取消不会更换证书。更换同端口证书会短暂重启 HTTPS 监听器，失败时尝试恢复原监听器；恢复也失败时保留原配置并提示重启服务。

导入的证书必须包含浏览器实际访问的 IP 或域名（SAN）。受浏览器信任的公共 CA 证书可直接通过相应域名访问；自签名证书仍需按车机支持的方式建立信任。域名解析自行配置，导入不会签发证书或修改 DNS。

## 音频行为

浏览器播放采用有界缓冲：服务端最多保留 16 帧待发音频、四帧等待确认，超过 100 ms 的待发帧被丢弃以避免不断增加延迟。浏览器麦克风发送 20 ms PCM 帧，并在服务端沿用 CarPlay 加密音频上行链路。实际车机对证书安装、音频焦点、回声消除与延迟的支持仍需分别验证。
