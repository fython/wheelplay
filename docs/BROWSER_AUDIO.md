# 浏览器音频与麦克风

在 Android App 的「设置 → 画面与音频」分别打开「转发音频到浏览器」和「使用浏览器麦克风」。两项默认关闭，可单独切换并立即生效；断开时暂时恢复 Android 路由，重新配对后会继续使用已保存的设置。浏览器可能要求点按画面以启动音频播放，网页不提供转发开关。音频播放可在普通局域网 HTTP 页面使用，与现有 JPEG / WebRTC 视频模式独立。

浏览器麦克风需要可信安全上下文。普通局域网 `http://设备地址:8080` 页面不能申请麦克风权限。配置步骤：

1. 在 Android 应用的「设置 → 权限与连接帮助 → 浏览器 HTTPS 证书」查看本设备的 SHA-256 指纹。在车机配对页展开「浏览器麦克风需要 HTTPS」，等待页面显示指纹并逐字核对，然后下载本地证书。
2. 在车机浏览器或系统中按其支持的方式信任此证书。随后打开页面提供的 `https://设备地址:8443/` 链接，重新配对。
3. 在 App 设置中打开「使用浏览器麦克风」，按浏览器提示授权。仅在 iPhone 发起通话或语音输入并要求麦克风数据时，浏览器采样才会发送到服务端。

证书的私钥只保存在 Android 应用的私有、非备份存储中。HTTPS 服务使用启动时检测到的局域网地址；网络地址更换后，重新启动服务再打开 HTTPS 入口。如果车机浏览器不能信任本地证书、禁用了麦克风权限或不支持 AudioWorklet，请使用 Android 麦克风。请勿通过浏览器的证书警告强行继续访问。

浏览器播放采用有界缓冲：服务端最多保留 16 帧待发音频、四帧等待确认，超过 100 ms 的待发帧被丢弃以避免不断增加延迟。浏览器麦克风发送 20 ms PCM 帧，并在服务端沿用 CarPlay 加密音频上行链路。实际车机对证书安装、音频焦点、回声消除与延迟的支持仍需分别验证。
