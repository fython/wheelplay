部分车机浏览器无法访问普通局域网地址。Tesla 兼容模式尝试通过另一个访问地址，让车机连接 Android 手机上运行的 WheelPlay Web 服务。名称沿用「Tesla 兼容」，也可用于存在同类限制的其他品牌车机。

**这是实验功能，不保证所有车机或 Android 系统可用。** 如果普通局域网地址已经可以访问，无需启用。它改变的是浏览器访问入口，不是新的投影输入源，也不会增加 CarPlay、Android Auto 或 VNC 的能力。

## 选择连接方案

两种方案都在 **设置 → Tesla 兼容（实验）→ 连接方案** 中选择，默认关闭。切换方案会关闭当前模式，需要再次主动启用；各自的地址设置会保留。两者均不提供第三方 VPN 的互联网转发。

| 方案 | 需要的权限 | 默认 HTTP 入口 | 端口规则 |
| --- | --- | --- | --- |
| 免 Root VPN（实验） | Android VPN 授权，无需 Root 或 Shizuku | `http://6.6.6.6:8080` | 使用实际 Web 监听端口，没有 80／443 映射 |
| Root 热点路由 | 已 Root 的设备及 WheelPlay 的 Root 授权 | `http://100.96.0.1/` | 默认将 80／443 映射到 Web 监听端口 8080／8443 |

表中地址是默认示例。实际使用时，以 App 显示的完整地址为准；修改 IP、域名或端口后，不要继续使用旧地址。

## 开始前的准备

1. 在 Android 宿主上启动 WheelPlay，确认 Web 服务正在运行。仅使用 CarPlay 时需要有效的认证资源；兼容入口本身不要求连接 iPhone。
2. 在同一台 Android 设备上开启**系统热点**，让车机连接这个热点。此模式不会修改系统热点的 IP 或 DHCP 网段。
3. 在车辆停稳后配置和测试。建议先用另一台手机或电脑连接热点，确认入口可达，再用车机测试。

普通局域网 Web 入口独立运行。兼容方案失败时，仍可尝试 App 显示的普通局域网地址。

## 免 Root VPN（实验）

1. 选择 **免 Root VPN（实验）**，开启模式并接受 Android VPN 授权。拒绝后模式保持关闭；需要恢复时，点击 **授权或重试 VPN**。
2. 等待 App 显示「免 Root 地址已配置」，再在车机输入完整地址，例如 `http://6.6.6.6:8080`。若修改过 Web 监听端口，请使用新的端口。
3. 按[使用指南](/docs/)完成浏览器配对并启动显示，然后连接所需的输入源。
4. 若有线 CarPlay 已连接，启用模式、修改访问 IP 或重建地址时，先断开 iPhone。App 会等待断开后应用变更；关闭免 Root 模式本身不会停止有线 CarPlay。

此方案占用 Android 的 VPN 槽位，不能保证与其他 VPN 同时使用，也不提供互联网 VPN 服务或系统 Always-on VPN。关闭模式、停止 Web 服务或撤销 VPN 授权后会清理兼容地址；撤销授权后需要手动重试。

“地址已配置”只表示手机上检测到了地址，不能证明热点回程、车机浏览器或 WebRTC 已经可用。不同 Android ROM、热点防火墙和系统更新可能影响结果。

`6.6.6.6` 是公网地址形式，并非 WheelPlay 提供的公网服务器。正常配置时用于本地投递；如果地址或路由失效，请求可能被送往上游。因此不能仅凭状态提示断言流量始终留在局域网。

## Root 热点路由

此方案需要已 Root 的 Android 设备，以及可用的 `su`、`ip` 和 `iptables`。相关路由适配已内置，无需另装 VPN Hotspot。

1. 选择 **Root 热点路由**，点击 **请求 Root 权限**，在 Root 管理器中授予 WheelPlay 权限。检查成功后开启兼容模式。此方案本身不申请 Android VPN 授权。
2. 默认共享 IP 为 `100.96.0.1`。若自行修改，避免与移动网络、其他 VPN 或局域网地址冲突。
3. 默认 HTTP／HTTPS 映射端口为 `80`／`443`，可配置为不同的 `1–1023` 端口；它们转发到 **设置 → Web 服务** 中的实际监听端口。HTTPS 映射仅在 HTTPS 已开启且监听成功时生效。
4. 等待「Root 热点路由已启用」，在车机打开 App 显示的完整入口并配对。默认 HTTP 地址为 `http://100.96.0.1/`；使用非默认映射端口时，需要在地址中带上端口。
5. 授权被拒绝、命令缺失、端口占用或规则安装失败时，先解决 App 提示的问题，再点击 **重新启动 Root 路由**。应用不会持续重复申请 Root。

关闭模式、停止 Web 服务或关闭热点会撤销对应规则。配置保留，已启用的 Root 方案在应用进程重新启动后会再次检查权限。若提示清理失败，请按提示检查或重启设备，不要假定旧规则已被移除。

Root 路由与 iPhone 会话独立；有线 CarPlay 自身仍需原有的 Android VPN 授权，不因选择此方案而免除。

## HTTPS、域名与配对

- HTTPS 在 **设置 → Web 服务** 中单独开启。免 Root 方案使用实际 HTTPS 监听端口（默认 `8443`）；Root 方案可使用配置的映射端口（默认 `443`）。
- 证书必须覆盖实际访问的 IP 或域名，并被车机浏览器信任。默认本地证书会随访问地址或域名变化刷新；自定义证书需要自行确认覆盖范围。不要通过忽略证书错误来配置浏览器麦克风。
- 填写自定义域名不会自动配置 DNS，需要自行将其解析到实际访问 IP。
- 更换协议、地址或端口会改变浏览器来源，需要重新配对。兼容入口沿用原有配对、设备撤销和单浏览器控制规则。
- 浏览器麦克风仍需可信 HTTPS、浏览器能力及权限，而且仅在对应[输入源](/docs/sources/)支持时可用。

## 无法连接时如何排查

1. **先检查热点和入口。** 确认车机连接的是运行 WheelPlay 的手机热点，Web 服务已启动，方案已授权且启用，并输入 App 显示的完整协议、地址和端口。
2. **用另一台热点客户端测试。** 如果手机或电脑也无法打开，先排查 Android 端权限、热点、端口与路由状态；如果它能打开而车机不能，检查车机浏览器策略，以及地址是否被强制改成 HTTPS。
3. **页面可达后再检查画面。** WebRTC 的 ICE／UDP 可达性需要单独验证，页面能打开不等于视频直通可用。失败时可使用图像兼容模式。
4. **按方案处理提示。** 免 Root 模式提示地址消失或授权撤销时，关闭或手动重试；提示等待有线 CarPlay 断开时先断开 iPhone。Root 模式按具体错误处理，清理失败时先检查或重启设备。
5. **反馈时附上环境。** 记录手机型号、Android／ROM 版本、车机固件、连接方案、访问地址、是否强制 HTTPS，以及另一台热点客户端的测试结果；可从 App 导出诊断报告。

自动化检查不能代替实际 Android 路由、热点和车机浏览器验证。更多实现与验证范围见仓库中的 [Tesla 兼容模式说明](https://github.com/fython/wheelplay/blob/main/docs/TESLA_HTTP.md)。
